## 1. 项目概述

### 1.1 背景

高校教师与学生的课表通常依赖教务网站、纸质表格或社交群通知，存在"查一次要登录一次、离线打不开、多学期混在一起看不清"的问题。本项目要做的是一个**纯本地、零网络依赖、零登录**的课表管理应用：所有数据保存在设备沙箱内的**关系型数据库**中，打开即用，断网可用。

面向的核心用户是**教师**（一学期带多个班级、同一门课多个时间段），因此数据模型围绕"教师 → 课程 → 班级 → 时间段"四级结构组织，并支持多学期并行管理与按教师视角切换查看。

之所以选择关系型数据库而不是 JSON 文档，是因为课表数据天然是**强关联、强约束**的：同一班级被多门课引用、周次与时间段是一对多、学期与教师是层级关系。用文件存储时必须自己维护这些关系（因而出现"按班级名拼文件名""改名就丢名单""冲突判定跨不了文件"等结构性问题），而关系库把关联键、唯一约束、级联删除、事务原子性直接交还给数据库。详见 [02-数据库设计 §1](02-数据库设计.md#1-存储选型决策)。

### 1.2 设计目标

| 编号 | 目标 | 说明 |
| :--- | :--- | :--- |
| G1 | 离线优先 | 全部功能不依赖网络与服务器，数据落在应用沙箱 |
| G2 | 快速查看 | 冷启动后 1 屏内看到"本周 + 当天"课表，左右滑动切周 |
| G3 | 录课高效 | 新增一门课（含班级、时间段、颜色）在一页内完成，支持复制 |
| G4 | 多学期隔离 | 学期之间数据独立，切换学期不影响其他学期数据 |
| G5 | 时间表可配置 | 节次数、每节起止时间、课表模板可自定义与复用 |
| G6 | 数据可迁移 | 支持课表导出到系统文件、从文件导入，换机不丢数据 |
| G7 | **数据强一致** | 任何一次保存要么完整生效要么完全不变；进程随时被杀都不产生半截数据 |
| G8 | **约束由存储层兜底** | 人数非负、节次区间合法、周次在学期范围内、颜色格式正确等规则不只在界面校验，写进数据库约束 |
| G9 | **课表之外的个人事务** | 待办与课表数据完全独立（不挂学期外键），支持清单 / 重复任务 / 回收站；「学习」清单反过来消费当天课表 |

### 1.3 范围界定

**包含（In Scope）**

- 课表周视图浏览、周次切换、日期跳转
- 课程的增删改查，含多班级、多时间段、自定义颜色
- 班级与学生名单管理
- 教师信息管理
- 学期管理（新建 / 删除 / 切换 / 批量删除）
- 课表时间模板管理（节次数、每节时长、起止时间）
- 课表分享包导出 / 导入（zip：manifest + 两张 xls）；教务「教师个人课表」网格表识别导入
- 课堂签到（点名）：左滑旷课 / 右滑请假 / 长按拖圆环评级，考勤与成绩导出
- 上课提醒：次日 22:00 提醒 + 课前 N 分钟提醒（系统代理提醒）
- 待办：任务 / 子任务 / 清单 / 重复任务 / 回收站 / 应用内提醒
- 桌面卡片（2*2 / 2*4）：当天未上的课、点击跳转
- 全局设置（界面颜色、上课提醒）、关于页

**不包含（Out of Scope）**

- 账号体系、云端同步、多设备协同
- 人脸识别、扫码签到等硬件相关签到方式
- 教务系统账号对接 / 在线自动同步（仅支持**文件级**导入：Excel、分享包、教务网格表）
- 教室占用冲突检查（数据基础已具备，本期不做独立维度）
- 系统级日历写入 / Calendar Kit（代理提醒额度受管控，当前提醒只做到系统通知 + 应用内两级）

> 说明：「签到」已从早期的占位入口落地为完整功能（见 §3.12）；「上课提醒」也已落地（见 §3.10）。

### 1.4 存储方案约束（硬性）

| 编号 | 约束 |
| :--- | :--- |
| ST-1 | **业务数据一律存入 ArkTS 内置关系型数据库**（`RelationalStore` / `@kit.ArkData`），不使用 JSON 文件存储课表、学期、教师、班级、学生等业务数据 |
| ST-2 | 数据模型必须**关系化**：实体拆表、外键关联、用主键而非名称做关联键 |
| ST-3 | 跨表的写入必须**事务化**，不允许出现半截数据 |
| ST-4 | JSON 仅允许用于**双向的文件交换**（导入 / 导出）与**旧数据一次性兼容导入**，不得作为运行期存储 |
| ST-5 | 表结构变更必须有**版本迁移机制**，不得要求用户重装应用 |

## 2. 用户角色

本项目为**单机应用**，不存在服务端权限模型，角色按"使用视角"划分：

| 角色 | 描述 | 核心诉求 |
| :--- | :--- | :--- |
| 教师（主要） | 一学期承担多门课、多个班级，需要按教师维度查看与切换 | 快速录课、按教师切换课表、看清教室与周次 |
| 学生（次要） | 只查看自己的课表 | 快速定位当天课程与教室 |
| 数据搬运者 | 需要把课表发给别人或换机 | 一键导出、一键导入 |

**当前版本一次只展示一位教师的课表**（通过"教师姓名"下拉切换），这是因为课表视图按当前选中的教师主键渲染，而非把全部教师课程叠加显示。选中的教师会被持久化，下次打开保持。

| FR-VIEW-07 | 点击日期可跳转到指定日期所在周 | 中 | 跳转后周次、网格同步刷新 |
| FR-VIEW-08 | **点击课程块弹出「课程详情」半模态**（课程名/班级/人数/类型/学分/教师/时间/周次/教室/备注），内含「编辑 / 删除」二级菜单 | 高 | 详情通过 `bindSheet` 从底部弹出；「编辑」再分支为「编辑此班级 / 编辑此课程」跳 `pages/CourseEdit`；「删除」分本周一次 / 本班级 / 本门课三档；关闭后课表刷新 |

| FR-VIEW-10 | 非本周周次也能正常查看（仅本周高亮） | 低 | 高亮只影响视觉，不影响数据 |
| FR-VIEW-11 | 底部 Tab 切换"首页 / 我的" | 低 | 图标 + 文字标签（图标用 `ic_home` / `ic_mine`，SVG + `fillColor`），选中态图标与文字同取主题色、未选中 `#6B7280`；导航栏是**完全透明浮层**——只输出图标与文字，底下那一层的课表信息（含文字）原样可见、不被糊掉；切换不丢失课表滚动位置与当前周 |
| FR-VIEW-12 | **进入课表默认落在"今天所在周"** | 高 | 学期进行中时，冷启动、首次加载、切换学期都默认显示今天所在周（如第 7 周），不是每次第 1 周；同一学期内的刷新（编辑返回等）保留用户当前浏览的周次不跳周 |
| FR-VIEW-13 | **学期已结束时顶部提示「已结束」** | 中 | 选中学期已过最后一周周日时，顶栏第一行显示`学期名 · 已结束`（不再显示无意义的"第 N 周"）；点击日期跳周的入口改为提示"没有当前周可跳转" |

| FR-VIEW-16 | **屏幕上下两条系统栏（状态栏 / 底部导航条）的底色与页面底色一致** | 中 | 状态栏走 `statusBarColor`；**底部手势导航条区域没有背景色 API**（`navigationBarColor` 只对传统三键导航生效），那块画的是**窗口底色**，因此必须用 `setWindowBackgroundColor()` 把窗口底色也设成页面底色。两处与四个页面的页根同取 `common/Util.ets` 的 `PAGE_BG_COLOR` 一个常量 —— 任一漂开，屏幕边上就是一条白边 |

**业务规则**

- **BR-VIEW-1**：一门课在某周某天是否显示，取决于该课程该时间段的周次集合是否包含当前周次。若"单周/双周"模式，则按奇偶周过滤。
- **BR-VIEW-2**：周次计算以学期起始日**所在周的周一**为第 1 周起点，同周内任意日期均属第 1 周；结果夹紧在 `[1, total_weeks]`，超出视为学期外。
- **BR-VIEW-3**：当同一格出现多个课程时间段时，按录入顺序纵向排列并平分格高。
- **BR-VIEW-4**：当前周次的展示不得影响数据 —— 切周只改变视图，不触发任何写入。
- **BR-VIEW-5**：默认周次 = 今天所在周。学期**进行中**取真实周次；学期**尚未开始**或**已结束**时没有"今天所在周"，统一退回第 1 周。仅"冷启动 / 首次加载 / 切换学期"会重算默认周次，同一学期内的刷新保留用户所在周（编辑课程返回不跳周）。
- **BR-VIEW-6**：学期是否结束的判定口径与`isDateInSemester`一致 —— 以第一周周一为起点、`total_weeks × 7` 天后的前一天（最后一个周日）为学期末日，今天晚于该日即视为已结束。
- **BR-VIEW-7**：底部导航栏是**完全透明的浮层**，除了两枚图标与两行文字不输出任何像素，"透过"是三件事同时成立的结果 —— ① `barOverlap(true)` 让 TabContent 铺到导航栏之下（SDK 默认 `false`，不设则导航栏底下是空的）；② `barBackgroundColor(Color.Transparent)` 显式全透明底色（SDK 默认就是 `Color.Transparent`，写出来是钉住语义）；③ `barBackgroundBlurStyle(BlurStyle.NONE)` 关掉毛玻璃（SDK 默认 `NONE`，一旦用 `Regular` 之类的毛玻璃就会把底下的课表糊成色斑、文字读不出来）。tab 格子自身**不得有底色、也不得画分隔线**（实心格子或 1px 线都会挡住/横切底层文字）。因为导航栏压在内容之上，**滚动内容末尾按 `LAYOUT.tabBarHeight` 留白**，否则最后一屏内容永远被导航栏压住、点不开。
- **BR-VIEW-8**：左右滑动切周是**三页轮播**（上一周 / 当前周 / 下一周），三页共用一份"槽位 × 页宽 + 跟手位移"的横向坐标。相邻两页的课程**在切周时同步预载**（与当前周一起构成 `lessons / prevLessons / nextLessons` 三份数据），因此手指推出去看到的一定是**真实课表**，不是占位。松手翻页必须先播完动画、再在**同一帧**里"换数据 + 位移归零"（`commitWeek` 直接轮转三份数组、不回表），否则会出现"标题已是第 N+1 周、格子还是第 N 周"的空档。未越过阈值、或那一侧没有相邻周（学期边界）、或手势被系统打断，一律动画回弹 —— 即该次滑动被撤销，周次不变。
- **BR-VIEW-9**：课表是"读不到就一片空白"的形态，空白本身无法区分"这门课没排"与"读取失败"。因此**任何加载失败都必须留下可见痕迹**：`Index` 把失败原因落到 `loadError` 状态并在顶栏下方渲染红色提示条 + 「重试」，而不是只弹一个转瞬即逝的对话框。数据库连接的生命周期必须支持"关掉还能再打开"（`EntryAbility.onDestroy` 会 `close()` 连接，而 Repository 是进程内单例）—— 否则"退出后台再进入"会命中已关闭的连接，整屏课表空白，看起来就像**课程数据全丢了**。

- **BR-VIEW-10**：**页面底色只有一个定义**（`common/Util.ets` 的 `PAGE_BG_COLOR`）。四个页面的页根容器、`EntryAbility` 的窗口背景色（`setWindowBackgroundColor`）与状态栏 / 导航栏色全取它；页面里另有底板、输入框、未选中胶囊碰巧同值，那些是**控件底色**、不是页面底色，仍写字面量。理由是底部**手势导航条区域没有背景色 API**（`navigationBarColor` 只对传统三键导航生效），该区域默认透明、**透传窗口底色** —— 窗口底色与页面底色一旦不同，屏幕最下方就是一条白边（2026-09-23 真机截图取色：底部 33 vp 是 `#FFFFFF`，而页面是 `#F3F4F6`）。

### 3.3 课程与班级管理模块（FR-COURSE）

| 编号 | 需求 | 优先级 | 验收要点 |
| :--- | :--- | :--- | :--- |
| FR-COURSE-05 | 录入班级名称 | 高 | 班级名在全校范围内唯一；**关联一律走不可变 `class_id`，改名不影响既有课表与名单** |
| FR-COURSE-06 | 录入班级人数 | 中 | 默认 0；不得为负；人数与班级名单可相互参照（对账） |
| FR-COURSE-07 | 为班级选择显示颜色（HSV 拾色器） | 高 | 支持色板取色、色相条、饱和度/明度方形、透明度条、HEX 输入，默认 `#FFF0F0F0`；**统一归一化为 8 位 ARGB `#AARRGGBB`（v3 起，透明度真实生效）** |
| FR-COURSE-08 | 一个班级下可添加多个时间段 | 高 | 截图"时间段 1"；可复制、可删除 |
| FR-COURSE-09 | 时间段录入：周次范围（1-20 周）、星期、起止节次 | 高 | 截图"1-20 周 / 周一 / 1-2 节"；周次不得超出学期总周数 |
| FR-COURSE-10 | 时间段录入：教室、备注 | 中 | 教室显示在课表块上 |
| FR-COURSE-11 | 保存时检测时间冲突 | 高 | **双维度**：同教师维度（同一时间不能上两门课）+ 同班级维度（同一时间不能被两门课占用）；**检测到冲突必须提示而非静默丢弃**（见 BR-COURSE-2）；用户选择"取消"时**整次保存回滚，库里不留任何行**（见 BR-COURSE-5） |
| FR-COURSE-12 | 支持复制整个课程/班级生成副本 | 中 | 副本名称自动追加 `(1)`、`(2)` 递增序号；副本获得新的 `course_id`，`class_id` 复用 |
| FR-COURSE-13 | 支持删除班级或整门课程 | 高 | 删除需二次确认；删课程级联清掉其班级分组与时间段；**删班级前若仍被课程引用则拒绝删除** |
| FR-COURSE-14 | **保存是"整门课程"的单一事务** | 高 | 课程 + 班级分组 + 时间段 + 周次要么全部写入、要么一行都不写；保存后必须立即出现在课表中（不得出现"课程管理里数得到、课表上看不到"的课程）；**不允许保存一个时间段都没有的班级** |

**业务规则**

- **BR-COURSE-1**：班级名称在**全库范围内**唯一（数据库 `UNIQUE` 约束），作为展示标识；但所有关联键一律使用不可变的 `class_id`（UUID），因此**改班级名不会导致名单丢失或课表断开**。
- **BR-COURSE-2**：冲突判定标准为 —— **同一天（`weekday` 相同）且节次区间相交（`a.start ≤ b.end && b.start ≤ a.end`）且周次集合有交集**，三者同时成立才算冲突。判定范围包含两个维度：① 教师维度：同一教师、同一学期内所有课程；② 班级维度：同一班级被任意教师的任意课程占用。
  - 冲突时**必须**向用户返回冲突详情（冲突课程、班级、教室、重叠周次），由用户选择「替换 / 仍然保存 / 返回修改」，**禁止静默丢弃**。
  - 反例（不得判定为冲突）：区间相邻但不重叠（`1-2` 与 `3-4`）；周次无交集（第 1-5 周 vs 第 6-10 周，这是单双周轮转排课的常见形态）。
- **BR-COURSE-3**：课程唯一性由 `(学期, 教师, 课程名称, 课程类型)` 组合决定。
- **BR-COURSE-4**：学分字段可为空，**空值必须保持为空**，不得用 0 或任何默认值替代（"未填学分"与"0 学分"是两种不同的事实）。
- **BR-COURSE-5**：**一门课的保存是一个事务的边界**。课表是按 `v_lesson` 视图渲染的，它要求 `course / teacher / class_group / class_info / time_period / period_week` 六张表的行同时存在 —— 任何"课程写了、时间段没写"的中间态都会产出一门**永远不显示**的课程。因此：
  - 保存过程中**任一时间段冲突**（且用户未选"仍然保存"）→ 整体回滚，冲突详情交回界面；
  - 表单里必须至少有一个时间段（`班级 N 至少需要一个时间段`），从源头杜绝"没有周次所以没有课"的空壳；
  - 页面参数（学期 / 教师）非法时**禁止保存**（`parseInt` 失败得到 `NaN`，而 `NaN <= 0` 恒为 false，不能只判 `<= 0`）。

**业务规则**

- **BR-TIME-1**：默认模板节次数 12 节、每节 45 分钟，起止时间见 [数据库设计 §4.2](02-数据库设计.md)。
- **BR-TIME-2**：节次槽数量必须与 `class_sessions` 一致，修改节次数时同步增删槽位（同一事务内完成）。
- **BR-TIME-3**：节次槽的 `session_no` 必须从 1 起连续递增，不得跳号（否则时间轴与网格会错位）。
- **BR-TIME-4**：编辑页**不自动保存**——编辑动作只更新内存草稿并重算脏标记；点「完成」时把全部改动一次落库后出栈。**脏标记必须由"内容与载入时的快照比对"得出**：仅打开页面（异步回填触发的那次输入回调）不算改动，页头不得提示「有未保存的修改」；改了又改回原样也视为没改。
- **BR-TIME-5**：返回防丢失：有未保存改动时点「‹」或触发系统返回手势，弹「放弃修改？」确认框（继续编辑 / 放弃修改），放弃则不写库直接出栈。**未修改时不得弹框**（直接出栈）。
- **BR-TIME-6**：同一时刻只允许一次写库，写库期间忽略重复的「完成」点击，防止两个事务同时 DELETE/INSERT 同一张表的节次行。
- **BR-TIME-7**：名称留空时不允许把空串写进库——落库前兜底为「未命名时间表」（`name` 是 `NOT NULL UNIQUE`）。
- **BR-TIME-8**：复制产生的新表 `is_builtin` 强制为 0，且不带任何学期引用（`citation_count = 0`），保证立即可编辑、可删除。

| :--- | :--- | :--- | :--- |
| FR-WIDGET-01 | 提供桌面卡片，**支持 2\*2 与 2\*4 两种尺寸** | 高 | `form_config.json`：`defaultDimension` = `2*2`，`supportDimensions` = `["2*2","2*4"]`，动态卡片（`isDynamic: true`）；`module.json5` 注册 `type: "form"` 扩展能力。按官方设计规范，**小卡 2\*2 = 150×150 vp，中卡 2\*4 = 316×150 vp** —— 两者**同高**、2\*4 只是两倍宽（"2\*4 更高、能多放几节"是误解，早期四行挤在一起就是这么来的）；两种尺寸**都只显示两节**（`ROW_LIMIT = 2`），尺寸只决定**版式**（窄卡竖排 / 宽卡横排，见 FR-WIDGET-10） |
| FR-WIDGET-02 | 卡片显示**当天还没上完**的课程，最多两行 | 高 | 每行 = 一节（课程名 + 班级 + 上课时间 + 教室，左侧细色条取课程颜色，当天不足上限时只显示实际条数）。**两套版式**：窄卡（2\*2）每节课竖排两行 `课程名 / 左钟点上下排 + 右 教室与人数上下排`（班级与"第N节"不显示；钟点拆成上开始 / 下结束两行，合体写法在 150 vp 里会被截成 `10:55-1…`；**人数挂在教室下面一行**，不与教室争同一行的宽度）；宽卡（2\*4）每节课横排两行 `课程名 + 班级 / 第N-M节 · 钟点 + @教室 · N人`。教室在任何版式里都**不收缩**（不收缩的那一段永远是教室）；人数取该课班级登记人数（`class_group.population`），口径同课表页格子与课程详情，**为 0 不显示**。卡片上**基本不出现文字省略**：钟点 / 教室 / 人数（含宽卡全部文本）走自适应字号（`minFontSize` + `maxFontSize`）—— 被截成"@综合实验…"的教室等于没有，宁可小一号也要读全；**唯一例外是窄卡课程名**：固定 12pt、超长在末尾截断（`textOverflow(Ellipsis)`）—— 课名有班级与课表可对照，且缩字号会让同一张卡上两个课名一大一小。窄卡第二行**钟点贴左、教室与人数贴右**。**当天只剩一节课时**，课程块照常显示，**下一格留白**（卡片**固定两格**，格数不随"还剩几节"变——只剩一格时那个课程块会被拉满整张卡，看起来像数据没装配对；留白但**保留占位**）；《今天没课啦》因此**只在"当天一节都不剩"时出现**。顶栏另有**课程数徽标**：今天 `剩 N 节`（还没上完的）、明天 `共 N 节`（当天全部），见 FR-WIDGET-13 |
| FR-WIDGET-09 | **只显示"还没上完"的课，不显示已经上过的课** | 高 | 目标是「今天」时，按当前钟点滤掉**已下课**的课：判据为"课程**结束**钟点 > 当前钟点"（正在上的那一节**保留**，用户此刻最需要确认教室）；作息模板查不到钟点时一律保留；22 点后目标是明天，整日不过滤。当天已经没有任何"未上完"的课时，空态显示 `今天没课啦ヽ(*≧ω≦)ﾉ`（窄卡颜文字另起一行）—— **这是这句话唯一出现的地方**（"今天本来就没课"与"今天全上完了"对用户是同一件事，成因区分只留在日志里）；"只剩最后一节课"时下半格留白，不再借这句话 |
| FR-WIDGET-10 | **两种尺寸的信息量必须按宽度取舍**（窄卡少而清，宽卡全而准） | 中 | 窄卡宽度只有 150 vp：每节课只有两行 —— 课程名**独占一行**以求完整（与班级同行会把长课名截成"数字信号…"），第二行左边把钟点拆成**上下两行**（上开始 `10:55` / 下结束 `12:35`）、右边是教室与人数（**也是上下两行**）；"第N节"与班级不显示（它们能从课名推出）；宽卡 316 vp：信息与应用内的**课程块**一致（课程名 / 班级 / 教室 / 人数），并把**课程类型**并进课程名，形如 `数字信号处理（理论）` |
| FR-WIDGET-13 | 顶栏显示**课程数徽标**（今天还剩几节 / 明天共几节），**窄卡不显示周数** | 高 | 周数后面加一个课程数：**今天** = 当天**还没上完**的节数（`剩 N 节`，与卡片列出的内容同一份数据，卡片只列 2 条、N 可以更大）；**明天** = 当天**全部**节数（`共 N 节`）；当天一节都不剩时**为空串**（空态那句已经说清了，不再标 0）。颜色取 `app_setting.today_color` —— **与应用里"今天"日期徽标同一个高亮色**（卡片进程读不到设置，颜色随数据推过来）。**窄卡（2\*2）不显示周数**，只留这一格：150 vp 宽一行放不下"标题 + 周数 + 课程数 + 图标"四样，而"今天还剩几节"比"这一周第几周"要紧 |
| FR-WIDGET-12 | 卡片**顶部右上角显示应用图标**；文本降级上**只有窄卡课程名可以末尾截断** | 中 | 顶部一行 = 左 `今天 · 周三`、右 `第 N 周` + 应用图标 `ic_app`（14 vp，`Image($r('app.media.ic_app'))`，不收缩）—— 图标是这张卡片唯一的"身份标识"。钟点 / 教室 / 人数**单行显示但不省略**：用自适应字号（`maxLines(1)` + `minFontSize` + `maxFontSize`；卡片环境不支持 `heightAdaptivePolicy`）。**窄卡课程名单列一条**：固定 12pt + `maxLines(1)` + `textOverflow(Ellipsis)`，超长在末尾截断 —— 它是全卡唯一"截了还能猜"的信息，且缩字号会让同一张卡上两个课名一大一小、看着像两个层级 |
| FR-WIDGET-11 | **一节课都没有时，点卡片能进应用看课表** | 中 | 空态下**整张卡可点**（不只那句文案）：走 `postCardAction({action:'router'})` 但**不带时间段 id**，应用据此区分"打开某节课"与"只是看课表"—— 切回「首页」页签、收起可能还开着的面板、把课表对齐到**卡片显示的那一周**（周次在数据侧一算出来就写进契约，不再"有课才写"）。环境类空态（`还没有学期` / `学期还没开始|已结束` / `还没选择教师`）没有有效周次，传 0，应用只拉起、不动周次。**一张点了没反应的卡片会被当成卡片坏了**，而"今天没课"恰恰是用户最想去应用里确认课表的时候 |
| FR-WIDGET-03 | **22:00 之后显示次日课程（仅在允许"提前一天晚上十点通知"时）** | 高 | 取数时判断 `app_setting.notify_next_day`（=「我的 → 上课提醒」的**「提醒第二天的课」**，也就是"提前一天晚上十点通知"）**且当前小时 `>= 22`** → 目标日 = 明天，卡片标题相应变为`明天 · 周X`；**开关关掉时永远是今天**，标题里也不出现"今天/明天"（只剩下 `周X`）—— 用户在应用里没允许那条通知，卡片就不该在晚上变成一份没有标注的次日课表。目标日落在学期外时显示`学期还没开始 / 学期已结束`而非排课内容 |
| FR-WIDGET-04 | 取数口径与课表页一致 | 中 | 使用 `app_setting` 的**当前学期 + 当前教师**指针；切学期 / 切教师后卡片随之变化 |
| FR-WIDGET-05 | 卡片数据**定期刷新**，且应用内改动后及时体现 | 高 | 系统定时刷新（30 分钟粒度）+ 应用切前台 / 切后台时主动推送；卡片被删除后自动注销登记 |
| FR-WIDGET-06 | 卡片异常状态必须可区分，不得只显示空 | 中 | 文案分级：`正在加载…` / `数据读取失败` / `打开应用后可用` / `数据忙，稍后自动刷新` / `还没有学期` / `学期还没开始`｜`学期已结束` / `还没选择教师` / `今天没课啦ヽ(*≧ω≦)ﾉ`（今天已无未上完的课；窄卡颜文字另起一行）/ `明天没有课^-^`（22 点后）。**"今天没课"与"今天全上完了"共用同一句友好文案**，区分只在日志（`WSD_WidgetData` 会写明是哪一种），卡片上不再区分——对用户来说是同一件事。**"只剩一节课"不算空态**：那半格**留白**（2026-09-23 起；原先补的也是同一句`今天没课啦ヽ(*≧ω≦)ﾉ`）—— 卡片上还挂着课就不该说"今天没课啦"，留白但保留占位。于是这句话只在**真的没课**时出现 |
| FR-WIDGET-07 | **点击卡片上的某一节课 → 拉起应用并直接打开这节课的详情** | 高 | 卡片行点击走 `postCardAction({action:'router'})`，携带 `周次 + 时间段 id`；应用冷启动走 `onCreate`、后台走 `onNewWant`；首页据此**切到该周并弹出课程详情半模态**（内容同 FR-VIEW-08）；课已被删除时提示"已不在课表中"，不得静默无反应 |
| FR-WIDGET-08 | 卡片点课在"首页不在最前"时不得造成惊吓 | 中 | 用户停在全屏编辑页时，请求最长保留 2 分钟：超时静默丢弃；时间表编辑页在**没有未保存改动**时才自动退回首页让请求生效 |

### 3.12 课堂签到与考勤（FR-SIGNIN）

老师上课随时可能要点名，点完的结论又要能落进期末的平时分表里 —— 这一模块把"点名"与"导出考勤表"串成一条链：课程块 → 签到 → 全屏点名页（**列表视图**：滑动手势 + 长按拖到圆环上选档；**单人视图**：一屏一个学生、按钮记分）+ 只读的「查看本节课程情况」→ 班级名册导出（两种口径）。

| 编号 | 需求 | 优先级 | 验收要点 |
| :--- | :--- | :--- | :--- |
| FR-SIGNIN-01 | 课程详情面板的操作改为 **「删除 / 签到 / 编辑」**（签到居中） | 高 | 三键一行，签到放最常用的中间位；点它先给三个选项：「随机指定人数点名」（人数可调）/「全部点名」/「查看本节课程情况」（只读） |
| FR-SIGNIN-02 | 随机点名**人数可改**（默认 10，范围 1~200） | 高 | **± 步进器嵌在「随机指定人数点名」这一项标题的右侧**（不再单独占一行）：点 ± 只调人数、点标题才进点名页；标题下面那句提示里的数字读的是**同一个字段**，加减人数时一起变（`checkinRandomHint()`）。用步进器而不是输入框 —— 面板是 `FIT_CONTENT`，输入框会顶起软键盘把面板推高，高度一变内部点击就会命中旧布局（见 04 §12.3.2 第 17 点）；上限再夹到班级登记人数 |
| FR-SIGNIN-03 | 点名在**独立全屏页**进行，学生纵向列表 | 高 | 不用半模态：手势（水平滑 / 长按下滑）需要稳定命中的大区域，`FIT_CONTENT` 面板高度变化会让命中区错位；页面按 `time_period_id + week_no` 取"这一次课"的点名对象 |
| FR-SIGNIN-04 | **左滑 = 旷课**（导出 `×`）、**右滑 = 请假**（导出 `⊕`） | 高 | 位移判据取手势的**全局坐标差**（`fingerList[].globalX`，避开 `offsetX` 的 vp/px 单位歧义）；**再滑一次同方向 = 撤销**（误触的退路） |
| FR-SIGNIN-05 | **长按并把手指拖到圆环上**选等级 1~5，选中即"出勤 + 等级" | 高 | 圆环是**整圈**：正上方占 **1/3 圆（120°）** 的是**取消**（松手不改动原标记），剩下 **2/3 均分给五档（各 48°）**；基准"正上方 0°、顺时针为正"，于是 **正左 = 1 档、正下 = 3 档、正右 = 5 档**（与上一版半圆同一套手感）。判据是**角度落格**而不是"离哪个圆点最近"；手指没离开环心的**死区**（30 vp）内不选中任何档。几何是 `model/Attendance.ets` 里三个纯函数（`ringSectorOf` / `ringGradeAngle` / `ringOffsetOf`），由 `ringcheck.py` **用 node 实跑**反查（取消格必须 240/720 = 1/3、每档 96/720） |
| FR-SIGNIN-06 | **随机指定人数点名**：抽出来的 N 人直接作为点名对象 | 中 | Fisher–Yates 洗牌决定"这次点谁"，**不替老师下结论** —— 出勤与否仍由老师逐人滑出来 |
| FR-SIGNIN-07 | **一次点名占导出表的一列**，按周次 + 时段独立成列 | 高 | 导出表只有「考勤 1~5 / 课堂状态 1~5」十列 ⇒ 每门课最多导出**前 5 次**点名，列号按 `(week_no, weekday, start_time)` 排序确定 |

| FR-SIGNIN-13 | **单人视图**：一个学生一屏，用按钮记分 | 中 | **上半屏** = 当前学生（第 i / N 位、姓名、学号、状态符号、档位分数），**下半屏** = 两行操作键（**切换视图 + 1 + 2 + 3** / **4 + 5 + ⊕ + ×**，图标 `ic_switch`），最底下则是**两端对齐**的前后两位学生（`ic_lastUser` 贴左、`ic_nextUser` 贴右；按钮按内容宽收小、姓名与学号分两行、中间不再夹 `·`，点到头变淡且不响应）。入口是列表**最底下那个「单人视图」按钮**（进去停在**第一位还没点名的学生**；**行本身不可点** —— 一行已有三种手势，再加"轻点"会和长按的 320 ms 判定抢手指）；等级键"再点一次同档 = 撤销"，与手势同一套退路；**不自动跳下一位**（老师点完可能还要改口）；顺序取**点名对象**，不首尾环绕（见 04 §12.3.2 第 (29)、(30) 点） |

## 6. 验收标准

| 编号 | 验收场景 | 通过标准 |
| :--- | :--- | :--- |
| AC-01 | 首次安装启动 | 自动创建数据库（**14 表 / 2 视图 / 14 索引**，`user_version = 7`）并生成默认学期 + 默认课表时间模板 + 示例课程，课表页可正常显示 |
| AC-02 | 新增一门课 | 在添加课程页填完课程/班级/时间段后保存，返回主页对应周次格内出现该课程，颜色正确；该次保存是**单一事务**（课程 + 班级 + 时间段 + 周次一次写入），若因冲突被取消则库里一行都不留 |
| AC-03 | 冲突保护 | ① 同一班级录入重叠时间段时被拒绝并给出**含周次的重叠详情**；② 同一教师在不同课程录入重叠时间段时同样被拒绝；③ 第 1-5 周与第 6-10 周（无交集）**不**被判为冲突；④ 用户可选择"仍然保存"强制写入；⑤ 用户选择"取消"后，本次新增的课程**完全不存在**（不产生"有课程没时间段"的空壳） |
| AC-04 | 切换教师 | 选择另一位教师后，课表只显示该教师课程；重启应用后仍停在该教师 |
| AC-05 | 切换学期 | 切到另一学期后课表内容与周次全部刷新，切回原学期数据完好 |
| AC-06 | 修改节次数 | 把 12 节改为 10 节后，时间轴与网格同步为 10 行，原第 11、12 节的课**不丢失**（仍在数据中，恢复节次数后可再显示） |
| AC-07 | 杀进程恢复 | 点保存后立即杀进程，重启后数据仍在 |
| AC-08 | 导出导入 | 导出 JSON 后清空数据，再导入该文件，课表恢复到导出前状态 |
| AC-09 | 折叠屏 | 在折叠/展开状态下设置面板与导航栏宽度适配正常，无溢出 |
| AC-10 | 全流程无障碍 | 课程块的**字色只取纯黑或纯白**，且取二者中对比度更高的那个（深底白字 / 浅底黑字），按 WCAG 相对亮度判定；`#1890FF` 这类中亮蓝用黑字（6.47:1），深蓝 / 深紫用白字 |
| AC-11 | **事务原子性** | 在保存过程中人为中断（杀进程），重启后该次保存要么完全生效、要么完全不变，不出现"课程有了但时间段没有"的半截数据 |
| AC-12 | **旧数据升级** | 设备上是 v1.0 版本的 JSON 数据时，升级安装后自动导入全部数据，课表与旧版一致；旧 JSON 被归档到备份目录，再次启动不重复导入 |
| AC-13 | **班级改名不丢数据** | 把一个已被课程引用的班级改名后，课表块显示新名称、该班学生名单依然完整可查 |
| AC-14 | **约束拦截** | 通过任何途径（包括导入文件）尝试写入非法数据（负人数、`end_time < start_time`、8 位颜色值、0 周）均被拒绝或自动归一化，库中不存在非法值 |
| AC-15 | **退出后台再进入数据仍在** | 退出应用（Ability 被销毁、连接被 `close()`）后重新进入，课表与"我的/管理"面板数据完整；无论进程是否被系统回收（连接关闭后重新打开 / 全新进程），表现一致 —— 不得出现"所有课程都不显示了" |
| AC-16 | **保存后即刻可见（引用键完整）** | 新增 / 修改一门课后，它的时间段**立即**出现在课表上，退出重进仍在；课表管理与学生管理对「课程数 / 班级数」的统计**一致**；库中不存在 `class_group.class_id` 为空串或指向不存在班级档案的分组 —— 一旦出现（历史数据），启动时自动修复 |
| AC-16b | **切换教师后重启仍停在该教师** | 在「教师管理」里切到 B 老师（课程都建在 B 名下）→ 退出应用 → 重新进入，课表仍显示 B 老师的课程（`app_setting.teacher_id` 已落盘） |
| AC-17 | **课堂签到与考勤导出** | 在一节课上点「签到 → 全部点名」：左滑 2 人（旷课）、右滑 1 人（请假）、长按下滑给 3 人评 3 等；点「完成」返回后打开该班名册导出 —— 原表口径下考勤列出现 `×` / `⊕`、课堂状态列出现 `3`；同一次换「算分后导出」，考勤列这 3 人变 `√`、课堂状态列变 80~84 之间的分数，**两次导出的分数完全一致** |
| AC-18 | **查看本节课程情况（只读）** | 同一次「全部点名」保存后再点「签到 → 查看本节课程情况」：面板四格计数（出勤 / 旷课 / 请假 / 未点名）与刚才的操作一一对上，已评级平均分落在 65~95 之间；列表按学号升序、每行右侧记号与点名页一致；点「返回」退回**签到面板**（不是课程详情）；整个过程不写库（退出重进结果不变） |
| AC-19 | **圆环选等级（1/3 是取消）** | 在一个学生上长按不动 0.3s 以上：其余学生的行上出现阴影、被按的那一行浮起，圆环出现在手指处；把手指拖到**正上方**（「取消」）松手 —— 该学生**仍然保持原来的状态**（不改动）；再长按拖到**正左 / 正下 / 正右**松手，分别得到 1 / 3 / 5 档与对应区间内的分数；长按后立刻松手（手指没离开环心）同样不改动任何数据 |
| AC-20 | **单人视图** | 在名单**最底下**点「单人视图」按钮：进入单人视图、停在**第一位还没点名的学生**（**上半屏**显示第 i / N 位、姓名、学号、状态；**下半屏**是一排操作键，最底下左右两端是前后两位学生、姓名与学号分两行且中间没有 `·`）。顺手确认：**点名单里的某一行不会跳页**（点一下没反应，长按才评档）；点「3」→ 状态变 3 档并出现分数，再点一次「3」→ 撤销回未点名；点「⊕」「×」分别记请假、旷课；点右下 `ic_nextUser` / 左下 `ic_lastUser` 前后移动，到头时那一侧变淡且点了不动；点第一行的「切换视图」回到名单列表，滚动位置与刚才的点名结果都在；最后点右上角「完成」才落库 |
| AC-21 | **系统栏与页面底色一致** | 四个页面（首页 / 我的 / 课程编辑 / 课堂签到）屏幕**最底部那条系统导航条区域与页面同色**（`#F3F4F6`），不存在白边；`statusBarColor` / `navigationBarColor` / `setWindowBackgroundColor()` 三者取同一个 `PAGE_BG_COLOR`（`common/Util.ets` 唯一定义），由 `.workbuddy/tools/bgcheck.py` 脚本自证（14 个改坏用例） |
| AC-22 | **提醒额度可控（30 条）** | ① 任一条提醒弹出后，通知上带「知道了」（关闭）按钮，点它可释放额度；② 过滤 `WSD_LessonReminder`，每次重建都有 `提醒额度清点：清理前 N 条 / 清理后 M 条`；③ 人为把额度占满后，日志只出现**一条** `提醒额度已用满（1700002），10 分钟内不再尝试登记`，不再每次刷新都报错；④ 额度满时**已有的提醒不会被清空**（熔断期连清理都不做）。由 `.workbuddy/tools/remindercheck.py` 脚本自证（17 个改坏用例） |
| AC-23 | **待办闭环** | 右下角 **+** 建一条"每天"重复任务并设截止 → 列表出现在「今日」组；勾选完成后列表出现**下一条**（截止顺推一天），撤销完成**不会**再克隆出重影条（克隆前查重）；删除后进回收站、可恢复，30 天后过期项在进页时被自动清理；「学习」清单能看到当天课程，左滑标完成后该行划掉、再滑撤销 |
| AC-24 | **课表分享包导入** | 用 A 设备导出的 zip 在 B 设备导入：新增一个学期并自动切过去，课程 / 班级 / 时间段 / 周次与 A 完全一致，**B 原有的学期一行不改**；同名学期或同名时间表自动顺延序号；同一份包连导两次不会因 `course_id` 冲突失败 |
